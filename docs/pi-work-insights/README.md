# PI 工作洞察：工作观察 JSON 生产者

## 已确认的职责

从 PI 当前授权会话自动提取：

1. 用户最近的工作内容、目标、背景、进展。
2. 用户明确作出的选择与理由。
3. 未完成、待确认、受阻、待验证的事项。
4. 提示词表达、协作方式和工作方法上的偏好线索。
5. 支撑这些观察的必要短原话。

**生成结构化 JSON 就是插件交付终点。数据如何使用不属于插件。**

## 明确不做

- 不决定进记忆库、画像或“工作知识库”。
- 不跨会话归并、推导长期画像、做置信度打分。
- 不预测下一句、不提供建议 UI、不注入主 Agent 上下文。
- 不开发 backend / DeckZ 对接、传输服务或数据库。
- 不把自动生成的内容标成用户审核通过。

此前的审计批次方案、手动习惯管理和下一句预测方案均已停止推进。当前只保留自动提取所需的来源区分、隐私过滤、授权、取消、限额和简单文件输出。

## 输出约定

- 五个数组：`recentWork`、`decisions`、`openLoops`、`preferenceSignals`、`evidence`。
- 必须保留“明确表达 / 行为观察 / 助手建议 / 模型推断”的区别。
- 个人候选偏好、项目要求、临时任务要求不能混为一谈。
- 不知道就填 `null`，无内容就返回空数组，不凑画像。
- 引用必须匹配输入原话；来源、时间与角色由代码填充，不由模型声明。

## 本轮完成标准

- 一次明确授权后，正常任务结束并空闲时自动提取，不要求用户逐条确认。
- 实际输出可通过运行时 Schema、引用和跨字段校验；坏结果不发布。
- 用户开始新任务时让路，旧会话/授权的迟到结果不发布。
- 成功的相同输入不重复请求；请求数、输入/输出和磁盘使用有上限。
- 合成样例、生成 Schema、单元测试、真实 SDK 加载/自动触发冒烟可重复运行。
- 不在开发测试中擅自读取个人会话、调用付费模型或开启个人安装。

自动测试证明结构与行为边界，不证明模型语义质量；实际提取效果需另行明确授权后验收。
